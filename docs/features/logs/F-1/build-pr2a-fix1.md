## Watch items (not defects of this round)

- PR-1's `lib/auth/attempts.test.ts` "attestation first …" compares a global `count(*) from signup_attempts` before and
  after a rejected call. Test files run in parallel against one database and the F-1 tests create attempts
  constantly, so the two counts can differ by a concurrent insert. It failed once in six runs here, only while the
  guard ran alongside; it is the "flake that did not reproduce" in the PR-2a build log. A race-free form would assert
  on the rejected call's own effect (no row for that call) rather than a global count; left for a PR-1 fix since
  tests are never weakened in a fix round of another PR.
- `failure_reason = 'vendor'` now means the vendor refused or lost the link (401/403/404). The check constraint was
  not widened: the connections table is new in this PR and the schema allows no `drop`, so a new reason value would
  have needed a constraint change on every database that already applied PR-2a.
