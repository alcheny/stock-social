# Security review, 2026-11-01

Scope: the app as it stood on `claude/serene-faraday-f45ffc` before public launch. Method: eight independent reviewers,
one lens each (authentication and sessions; authorization of every server action and route handler; injection, headers
and redirects; secrets and logging; CSRF, clickjacking and headers; rate limits and abuse; webhooks and cron endpoints;
dependencies and supply chain). Their 38 raw findings were deduplicated into 30, and one more came from the parallel
privacy review (F31). Every finding was then put to three independent skeptics who tried to refute it from the code. A
finding is kept only when most skeptics fail to refute it. All 31 survived, many at a lower severity. The severity
below is the skeptics' consensus.

No exploit recipes are recorded here. Each entry says what was wrong and what the fix does.

## Shared rate limiting

`lib/rate-limit.ts#hit(key, limit, windowSec)` is a fixed-window counter in the `rate_limits` table. Each check is one
upsert, so every server instance shares the count. Keys never hold personal data: the value is an HMAC (`limitKey`),
emails are canonicalized for the key only, and IPv6 is cut to /64. Old windows are pruned in small batches by the
limiter itself. The client address is read only on Vercel or when `TRUST_PROXY_HEADERS=1`. Without a trusted address,
the per-client limits are skipped rather than pooled into one bucket that anyone could exhaust; the per-address and
overall limits still apply.

## Content-Security-Policy

Every page is dynamic, so `proxy.ts` sets a per-request nonce: `script-src 'self' 'nonce-…' 'strict-dynamic'`.
Styles keep `'unsafe-inline'` because React style attributes can't carry a nonce. `frame-src` allows https (the vendor
portal) plus the test vendor's origin when it is configured. `form-action` is left out because the OIDC form redirects
to each provider's authorization endpoint. A browser check of the main pages and the e2e suite ran with no CSP
violations.

## Review of the fix

An independent review of the final diff found no blocking issues. Its findings, all fixed in the same PR:
- **The vendor-registration cap held a shared row lock during the vendor call.** That serialized every first-time
  registration. The cap is now read before the mint's transaction and counted after it commits. Only the real vendor
  deps carry it, so test fakes don't feed it.
- **Client address handling:**
  - IPv4-mapped IPv6 addresses each get their own bucket;
  - behind a self-hosted proxy (`TRUST_PROXY_HEADERS=1`) only the rightmost forwarded hop is used.
- **Operator signal:** reaching an overall cap writes one non-personal log line per window.
- **Index:** on `rate_limits.window_start`, for pruning.
- **Test:** a behaviour test for the email-claim error path, which logs no address.
